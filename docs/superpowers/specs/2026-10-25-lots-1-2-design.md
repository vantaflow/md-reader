# MD Reader 1.8.0 et 1.9.0 — conception

Date : 2026-10-25. Deux lots livrés sur la branche locale `amelioration/lots-1-2`
(worktree `.worktrees/lots-1-2`), sans push, sans release, sans merge.

## Principes d'architecture (Rulings)

- Ruling : réglages dans une **modale intégrée** à la fenêtre principale (Cmd/Ctrl+,), pas une seconde BrowserWindow — appliqués à chaud sans IPC, testables par `executeJavaScript`, une seule fenêtre à garder invisible — coût si faux : changer en fenêtre dédiée plus tard.
- Ruling : magasin de réglages unique `renderer/lib/settings.js` (clé `localStorage` `reglages`, valeurs par défaut, `get/set/onChange`), migré depuis les clés existantes (`theme`, `modeAffichage`, `pdfOptions`…) — coût si faux : réglages perdus à la migration.
- Ruling : logique pure dans `renderer/lib/*.js` au format UMD (CommonJS pour `node --test`, global `window.lib…` dans le renderer via balise `<script>` ; la CSP `script-src 'self'` le permet) — testable sans Electron.
- Ruling : bibliothèques tierces utiles ajoutées (npm, MIT) et bundlées par esbuild dans le renderer : `docx` (export Word), `jszip` (EPUB), `mammoth` (import .docx), `turndown` (HTML vers Markdown). Pas de service réseau, sauf la vérification de mise à jour (API GitHub des releases) qui est déclenchée par l'utilisateur ou par un réglage activable.
- Ruling : tests. `npm test` exécute les tests node (`test/*.test.js`), puis `test/smoke.js` (existant, 146 contrôles, conservés) puis des scripts Electron additionnels `test/smoke-lot1.js`, `test/smoke-lot2*.js` partageant `test/helpers.js` (même modèle : fenêtre `show:false`, garde-fou 3 minutes, `check()`). Le nombre total de contrôles est la somme des sorties. Aucune fenêtre visible, aucune boîte de dialogue réelle : les dialogues sont stubés.
- Ruling : le mode focus déjà existant (`body.focus`, commande `vue:focus`) est conservé ; on ajoute « aperçu seul plein écran » et « éditeur seul sans distraction » comme modes de présentation distincts, `Échap` en sort.
- Ruling : le fichier `renderer/renderer.js` devient trop gros ; les nouvelles fonctions vont dans des modules `renderer/features/*.js` (scripts classiques chargés avant `renderer.js`, qui exposent `window.mdr` : accès à l'éditeur, aux réglages, à la palette, aux onglets). Le minimum de modifications est fait dans `renderer.js`.
- Ruling : correcteur orthographique via le correcteur natif de Chromium/Electron (`session.setSpellCheckerLanguages(['fr','fr-FR','en-US'])`, menu contextuel construit depuis `context-menu`/`dictionarySuggestions`), pas de dictionnaire embarqué — coût si faux : sous Windows/Linux les dictionnaires se téléchargent au premier usage.
- Ruling : fonctions « à confirmer par l'humain » non automatisables en test (installation réelle d'une mise à jour, collage dans Outlook/Teams) : la partie testable (HTML produit, parsing de la réponse GitHub avec `fetch` simulé) est testée, le reste est consigné dans le rapport.
- Ruling : tout ce qui écrit sur disque depuis le renderer passe par une IPC de `main.js` qui borne le chemin (dossier du document, dossier `images/`, dossier de données de l'application).

## Lot 1 — 1.8.0

1. **Réglages** (Cmd/Ctrl+,, menu, palette) : onglets Éditeur (police, taille, retour à la ligne, numéros de ligne, taille de tabulation, barre d'outils visible), Aperçu (mode par défaut continu / A4 / A4-double, police et taille de l'aperçu, marges des feuilles A4, thème clair / sombre / système), Export PDF par défaut (format, orientation, marges, numéros de page, page de garde, filigrane — mêmes champs que la modale d'export, qui s'ouvre pré-remplie), Général (autosave + délai, synchro du défilement, rouvrir les onglets au démarrage). Mémorisés, appliqués à chaud (CodeMirror reconfiguré via compartiments). Les en-têtes `Code`/`Sync`/`Autosave`/thème de la barre restent synchronisés avec les réglages.
2. **Menus** : Affichage (Continu, A4, 2 pages, thème clair/sombre/système, zoom avant/arrière/réinitialiser de l'interface, panneau latéral, éditeur seul / aperçu seul / les deux, plein écran, focus) ; Format (gras `CmdOrCtrl+B`, italique `+I`, barré `+Shift+X`, titres 1-3 `+Alt+1..3`, liste à puces `+Shift+8`, numérotée `+Shift+7`, tâches `+Shift+9`, lien `+K`, image `+Shift+I`, tableau `+Alt+T`, bloc de code `+Alt+C`, citation `+Shift+.`, saut de page `+Enter`) ; Fichier : Ouvrir récent (sous-menu, 10 entrées, « Effacer »), Enregistrer sous… (`CmdOrCtrl+Shift+S`), Dupliquer, Exporter en Word ; Aide : aide-mémoire Markdown, raccourcis clavier, À propos (version). Tout le Format passe par `renderer/lib/format.js` (fonctions pures sur `{texte, from, to}` testées en node) et par le registre de commandes (palette).
3. **Barre d'outils de mise en forme** au-dessus de l'éditeur, mêmes actions que Format, masquable via réglage et menu Affichage.
4. **Export Word (.docx)** : `renderer/lib/docx-export.js` convertit le HTML de l'aperçu (DOM) en document `docx` : titres 1-6, paragraphes, gras/italique/code/lien, listes à puces et numérotées imbriquées, tableaux, images (locales converties en octets, data URI), blocs de code (police monospace, fond), citations, filets. Enregistré via dialogue (IPC `file:export-docx`).
5. **Modes focus** : « Aperçu seul plein écran » (éditeur, panneau, en-tête masqués, aperçu plein écran) et « Éditeur seul sans distraction » (éditeur plein, centré, aucun autre élément) ; `Échap` en sort ; dans la palette et le menu.
6. **Image collée ou glissée** : copie dans `images/` à côté du .md (nom horodaté ou nom d'origine sans collision), lien `![](images/nom.png)` inséré. Document non enregistré : demande d'enregistrer d'abord (dialogue de confirmation), puis poursuite.

## Lot 2 — 1.9.0

**Écriture** : éditeur de tableau visuel (modale avec grille, ajout/suppression de lignes et colonnes, alignement par colonne ; s'ouvre sur un tableau existant ou crée) ; modèles de documents (compte rendu, spec, README, lettre) et snippets utilisateur (stockés dans le dossier de données, palette « Insérer un snippet… », « Nouveau depuis un modèle… ») ; correcteur FR/EN avec suggestions au clic droit ; reformatage du Markdown (listes renumérotées, tableaux alignés, espaces) ; emoji `:nom:` (table intégrée, autocomplétion + conversion dans l'aperçu) ; autocomplétion des liens `[](` et `[[` vers les .md du dossier ouvert.

**Navigation** : panneau Plan du document (clic = saut dans l'éditeur et l'aperçu ; glisser-déposer réordonne les sections du texte source) ; liens wiki `[[note]]` rendus et cliquables, panneau rétroliens (scan du dossier ouvert) ; rechercher/remplacer dans tous les .md d'un dossier avec aperçu des changements (diff par fichier, confirmation) ; favoris (fichiers épinglés, persistés) et filtre par tags du front-matter dans l'explorateur.

**Export et partage** : thèmes d'export PDF/HTML (sobre, rapport, académique) + CSS personnalisé ; export EPUB (jszip) ; mode diaporama (`---` sépare les slides ; plein écran, flèches ; export PDF des slides en paysage) ; « copier en HTML riche » (presse-papiers text/html + text/plain) ; import .docx (mammoth) et HTML (turndown) vers Markdown.

**Confort** : historique des versions (instantané à l'enregistrement dans le dossier de données, comparaison avec diff, restauration) ; mode présentation lecture (plein écran, taille ajustable, défilement automatique à vitesse réglable) ; statistiques avancées (objectif de mots avec progression, indice de lisibilité Flesch / Kandel-Moles pour le français, temps de lecture par section) ; vérification des mises à jour via `https://api.github.com/repos/vantaflow/md-reader/releases/latest`, comparaison semver, proposition d'ouvrir la page de téléchargement de l'installeur de la plateforme (aucune release publiée par ce travail).

## Livraison

Chaque lot : tests verts à 100 %, README mis à jour, version bumpée (`package.json`, `package-lock.json`, `installer.iss`), commit(s) en français. Lot 1 = 1.8.0, lot 2 = 1.9.0.
